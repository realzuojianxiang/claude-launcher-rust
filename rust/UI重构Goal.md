# Apple 风格前端 UI 重构 Goal 与实施清单

> 本文档仅用于梳理需求、制定 Goal 和执行计划，不代表现在开始修改代码。
> 执行时应先完成现状盘点和基线验证，再按任务清单逐步重构。

```text
请对当前项目进行一次生产级前端 UI 重构，目标是消除现有界面中的 AI 生成痕迹，并将视觉、交互和状态处理统一到 Apple Human Interface Guidelines（HIG）及 macOS Ventura / iOS 17 原生视觉语言。

请自主完成需求拆解、代码盘点、设计 token 统一、组件重构、页面适配、状态补齐、可访问性检查和回归验证。中途不需要因常规设计或实现决策向我确认，请在既定约束内连续推进，并在每个阶段保留简短进度记录。

- 维护 `UI审计清单.md`，逐项记录原问题、文件/组件位置、重构方案、完成状态和验证证据。
- 维护 `UI设计Token.md`，记录颜色、字体、字号、间距、圆角、阴影、动效、浅色/深色模式和组件状态规范。
- 每个阶段完成后立即更新记录，不能只在最后凭记忆补写。
- 每条记录必须包含日期、阶段、涉及文件、变更摘要、验证命令/结果和遗留风险；不得记录账号、密码或其他敏感凭证。
- 最终交付 `UI重构总结.md`，包含前后对比、功能回归结果、视觉检查结果、测试结果、未完成事项和后续建议。

核心约束：
1. 这是前端 UI 重构，不得改变现有业务流程、接口契约、数据口径、路由语义、权限逻辑和用户实际使用方式。
2. 开始修改前，先记录当前页面截图、关键交互、路由、接口调用、表单校验和构建/测试基线；不得在未建立基线前大范围改动。
3. 严格使用 Apple 风格：系统字体栈、克制的系统色、系统灰阶背景、统一圆角、轻柔阴影、适度毛玻璃、清晰字体层级、充足留白和 8pt 间距体系。
4. 彻底移除紫蓝渐变、教程感布局、僵硬对称、Lorem Ipsum、Item 1 和理想状态专用代码。不得用装饰性动效掩盖信息架构或交互问题。
5. 必须补齐 Loading、Empty、Error、Disabled、Hover、Focus、Active、提交中、校验失败、无权限和网络失败等真实状态；错误提示应温和、可理解且可恢复。
6. 动效必须有目的、跟手、连续且克制；优先使用 cubic-bezier(0.25, 0.1, 0.25, 1) 或经过验证的弹性效果，常规过渡控制在 0.2s—0.35s，且支持 prefers-reduced-motion。
7. 使用 CSS 变量集中管理颜色、字体、圆角、阴影、间距、层级和动效 token；支持浅色/深色模式，不得在组件中散落不可追踪的硬编码值。
8. 不引入第三方 UI 框架，除非项目现有依赖已经使用且移除会造成风险；优先基于现有技术栈和组件体系增量重构。
9. 检查防抖、节流、表单实时校验、重复提交、焦点管理、键盘操作、最小交互目标 44px、响应式布局和可访问性。
10. 每完成一个重构批次，都要运行项目现有的 lint、typecheck、unit test、build 和可用的视觉回归检查，并记录结果。

执行顺序：
- 先盘点项目结构和页面/组件边界；
- 再建立 UI 基线和设计 token；
- 然后按基础组件、布局导航、业务页面、状态和响应式适配逐层重构；
- 最后进行功能回归、视觉检查、深色模式检查、性能检查和文档交付。

文档交付顺序：
- 先建立 `UI重构记录.md`、`UI审计清单.md` 和 `UI设计Token.md`；
- 每完成一个阶段就更新对应文档；
- 全部验证完成后生成 `UI重构总结.md`，并在其中链接或引用各阶段证据。

完成条件：
- 目标页面和核心流程可正常使用，原有功能行为无回归；
- 生产构建、静态检查和测试全部通过；
- 浅色/深色模式、Loading/Empty/Error 等状态均可复现并验证；
- 不再存在示例占位文案、紫蓝渐变、失控阴影、随意圆角或无目的动画；
- 交付重构前后对比、变更清单、风险清单、验证结果和后续建议。

只有在发现无法自行判断的重大业务口径变化、需要新增外部权限、现有功能无法安全保持，或验证结果持续失败且需要产品决策时才暂停；普通 UI 取舍、代码组织和测试修复请自主完成。
```

## 专业需求定义

### 目标

将当前 AI 生成感明显的前端 UI 重构为具有 Apple 原生质感的生产级界面，同时保持业务功能、数据和使用流程不变。

### 非目标

- 不重写后端接口或数据库逻辑。
- 不改变业务规则、权限模型、路由含义和数据口径。
- 不为了视觉效果删除已有功能或隐藏异常状态。
- 不在没有证据的情况下替换技术栈或大规模引入依赖。

### 设计基线

| 类别 | 规范 |
|---|---|
| 字体 | `-apple-system, BlinkMacSystemFont, "SF Pro Text", "SF Pro Display", "Helvetica Neue", sans-serif` |
| 浅色背景 | 主背景 `#F2F2F7`，卡片 `#FFFFFF` |
| 深色背景 | 主背景按平台使用 `#000000` 或 `#1C1C1E`，次级层级 `#2C2C2E` / `#3A3A3C` |
| 系统色 | 浅色蓝 `#007AFF`、绿 `#34C759`、橙 `#FF9500`、红 `#FF3B30`；深色模式使用对应提升亮度的系统色 |
| 圆角 | 组件按层级统一，卡片通常 12—16px，按钮 8—14px，输入框约 10px；不得出现无依据的随机值 |
| 阴影 | 使用低透明度、多层、柔和阴影；禁止厚重单层黑色投影 |
| 间距 | 以 8pt 为基础，使用 4/8/12/16/20/24/32/40/48/64px 序列 |
| 交互目标 | 可点击控件最小 44×44px，键盘和焦点状态可见 |
| 毛玻璃 | 仅用于导航栏、吸顶/吸底操作栏等合适层级，并提供不支持 `backdrop-filter` 时的降级样式 |
| 动效 | 150—400ms 为主，禁止超过 500ms 的常规交互动画；支持 `prefers-reduced-motion` |

> 原始需求中个别数值存在截断或冲突（例如 Modal 圆角、字体字号和动效曲线）。执行时以实际平台、现有组件约束和可用性验证为准，不机械套用明显损坏的数值。

## 详细 TodoList

### 阶段 0：范围与基线

- [ ] 确认前端技术栈、启动命令、构建命令、测试命令和浏览器支持范围。
- [ ] 枚举路由、页面、布局、公共组件、表单、弹窗、列表和导航入口。
- [ ] 记录核心流程：进入页面、查询、筛选、提交、编辑、删除、分页、导入导出和异常恢复。
- [ ] 保存重构前的关键页面截图和交互录屏/文字记录。
- [ ] 运行现有 lint、typecheck、test、build，记录基线结果。
- [ ] 标记当前已知问题、不可改动的业务逻辑和高风险页面。
- [ ] 创建 `UI重构记录.md`、`UI审计清单.md` 和 `UI设计Token.md`，登记基线和文档责任范围。

### 阶段 1：代码与视觉审计

- [ ] 搜索并登记渐变、紫蓝色、重复颜色值、随机圆角、重阴影和线性动画。
- [ ] 搜索 `Lorem Ipsum`、`Item 1`、mock 数据和只覆盖理想状态的条件分支。
- [ ] 检查所有页面是否具备 Loading、Empty、Error、Disabled 和提交中状态。
- [ ] 检查表单防抖/节流、实时校验、重复提交、错误恢复和取消操作。
- [ ] 检查响应式断点、深色模式、键盘操作、焦点样式和最小触控目标。
- [ ] 输出按优先级排序的审计清单：阻断问题、功能风险、视觉问题、体验优化。
- [ ] 将审计结果同步写入 `UI审计清单.md`，每项包含位置、问题、方案、状态和验证证据。

### 阶段 2：设计 Token 与基础能力

- [ ] 建立颜色、字体、字号、字重、行高、间距、圆角、阴影和动效 CSS 变量。
- [ ] 建立浅色/深色主题变量和系统色映射。
- [ ] 建立毛玻璃、降级背景和 `prefers-reduced-motion` 的公共样式。
- [ ] 统一全局字体、页面背景、文本层级和默认交互状态。
- [ ] 增加焦点可见性、禁用态、错误态和高对比度下的基础规则。
- [ ] 在不改变业务行为的前提下，补充 token 使用说明和命名约定。
- [ ] 将最终 token、取值、使用范围和主题覆盖关系写入 `UI设计Token.md`。

### 阶段 3：基础组件重构

- [ ] 重构 Button：Primary、Secondary、Ghost、Danger、Disabled、Loading、Hover、Focus、Active。
- [ ] 重构 Card：基础卡片、分组卡片、毛玻璃卡片、深色卡片和可交互卡片。
- [ ] 重构 Input/Select/Textarea：默认、聚焦、错误、成功、禁用、只读和占位状态。
- [ ] 重构 Loading：旋转圈、骨架屏、轻微 shimmer，并避免布局跳动。
- [ ] 重构 Empty：说明文案、可选插画/图标和恢复操作。
- [ ] 重构 Error：温和提示卡、底部浮层、重试和错误详情展开。
- [ ] 重构 Modal/Sheet/Popover：层级、焦点陷阱、Esc 关闭、点击遮罩规则和响应式布局。
- [ ] 重构 List/Table/Form Group：分组卡片、缩进分隔线、行高和键盘可操作性。
- [ ] 为每个组件补充状态矩阵和最小可验证示例，禁止使用业务占位数据。

### 阶段 4：布局、导航与页面

- [ ] 重构全局页面容器、内容宽度、响应式边距和滚动区域。
- [ ] 重构桌面/移动导航、Tab Bar、吸顶/吸底操作栏和安全区域处理。
- [ ] 将页面信息按视觉层级重新分组，优先用留白和层级而非密集边框分隔。
- [ ] 按页面优先级逐页迁移到基础组件和 token，不直接复制粘贴局部样式。
- [ ] 保持路由、接口调用、权限、表单提交和业务反馈逻辑不变。
- [ ] 对复杂页面拆分容器、展示组件和状态组件，避免单文件继续膨胀。
- [ ] 在 `UI重构记录.md` 中登记每个页面的变更文件、保留的业务接口和回归结果。

### 阶段 5：生产级状态与交互

- [ ] 为每个异步请求补齐初始、加载、成功、空数据、失败、重试和取消状态。
- [ ] 为表单补齐实时校验、提交中锁定、成功反馈、失败定位和恢复路径。
- [ ] 对搜索、筛选、窗口 resize、滚动监听等高频事件增加合理防抖或节流。
- [ ] 检查所有可点击元素的 Hover、Active、Focus、Disabled 和键盘行为。
- [ ] 优化动效的跟手性、连续性和层级关系，移除装饰性动画。
- [ ] 对减少动态效果用户关闭非必要动画，并确保信息仍完整可用。
- [ ] 记录状态与交互变更的验证证据、兼容性结论和遗留风险。

### 阶段 6：验证与交付

- [ ] 运行 lint、typecheck、unit test、integration test 和 production build。
- [ ] 逐条回归核心业务流程，记录输入、操作、预期和实际结果。
- [ ] 对浅色/深色模式、窄屏/宽屏、键盘操作和异常网络进行验证。
- [ ] 检查截图对比：颜色、字体、间距、圆角、阴影、动效、状态和信息密度。
- [ ] 检查控制台错误、网络请求重复、布局抖动、性能回退和无障碍警告。
- [ ] 输出变更清单、未解决问题、风险、回滚方式、测试结果和后续建议。
- [ ] 生成 `UI重构总结.md`，汇总前后对比、功能回归、视觉检查、测试结果、未完成事项和后续建议。
- [ ] 确认未修改后端、接口契约、数据库、业务口径和用户操作路径。

## 验收标准

- [ ] 核心页面达到统一 Apple 风格，且无紫蓝渐变、占位文案和明显 AI 模板痕迹。
- [ ] 所有关键页面具备完整的加载、空数据、错误、禁用和提交中状态。
- [ ] 所有核心功能可按原流程完成，接口参数、权限和数据展示无变化。
- [ ] 浅色/深色模式均可用，响应式布局无严重溢出或遮挡。
- [ ] 可点击控件具备可见焦点和至少 44×44px 的交互目标。
- [ ] 动效在正常模式下自然、克制，在减少动态效果模式下不影响使用。
- [ ] lint、类型检查、测试和生产构建通过，且无新增控制台错误。
- [ ] 交付前后对比和完整验证记录。
